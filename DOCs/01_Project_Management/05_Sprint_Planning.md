# 05_Sprint_Planning

# DeployFix Lab Sprint Planning Guide

## Purpose

Provide a consistent framework for planning, executing, reviewing, and
closing every sprint.

## Sprint Duration

-   Length: 1 week (recommended)
-   Team Size: 3 members
-   Planning Meeting: Sprint Day 1
-   Review & Retrospective: Final day

## Sprint Lifecycle

1.  Sprint Planning
2.  Task Assignment
3.  Development
4.  Daily Progress Updates
5.  Testing
6.  Code Review
7.  Sprint Review
8.  Sprint Retrospective

## Sprint Planning Checklist

-   Define sprint goal
-   Select backlog items
-   Estimate effort
-   Assign owners
-   Identify risks
-   Define Definition of Done
-   Update GitHub board

## Team Responsibilities

### Technical Lead

-   Sprint planning
-   Architecture review
-   Integration
-   DevOps

### Backend Engineer

-   Backend APIs
-   Database
-   Authentication

### Frontend Engineer

-   UI
-   API Integration
-   Responsive Design

## Sprint Deliverables

-   Working feature
-   Updated documentation
-   Tested code
-   Pull requests merged

## Exit Criteria

-   All planned tasks completed
-   Tests passed
-   Documentation updated
-   Demo ready
